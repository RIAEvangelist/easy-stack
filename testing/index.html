Testing and evidence

One behavioral suite. Two real runtimes.

vanilla-test runs the same host-neutral stack contract in Node and Chrome, while focused Node suites verify packaging, browser globals, the site, and its server.

Suite boundaries

SuiteWhat it provesRunner
Shared coreLIFO order, synchronous start, pause/resume, active insertion, contents, validation, recovery, async hand-off, and isolation.vanilla-test in Node and Chrome
Playground controllerNewest-first display, cooperative and manual hand-offs, stop/release, clear/reset, and immutable state snapshots.vanilla-test in Node
Package contractESM, CommonJS, deep paths, classic globals, ES5 regression, metadata, and zero runtime dependencies.vanilla-test in Node
DocumentationEvery route, required section, asset, fragment, README link, workflow, and no-TypeScript contract.vanilla-test in Node
Local serverContent types, page/module/image delivery, containment, malformed paths, and missing files.vanilla-test in Node
Packed artifactThe npm tarball contains only intended files and installs in a clean consumer project.CI smoke process

On Node 22.12 and newer, every repository test uses vanilla-test@2.1.1. A dependency-free fallback runs all 22 behavior and package contracts on the exact Node 12.22.12 compatibility floor.

CI and publication gates

  1. Test Node 22.12 and 24 across Linux, macOS, and Windows.
  2. Run all dependency-free behavior and package contracts on exact Node 12.22.12.
  3. Collect native coverage in Node 24 and Chrome Stable.
  4. Pack the npm artifact, verify its file list, install it in a clean project, and exercise both import systems.
  5. Validate every documentation route and the contained local server.
  6. Assemble only curated site files and coverage reports.
  7. Deploy GitHub Pages only after every preceding gate passes.
Runtime dependency count: zero.

vanilla-test is pinned as development tooling and is excluded from the published runtime dependency graph.
